# 课题计划：从星系光谱摊销推断恒星种群参数

> 这是一份研究方向说明书，不是再做一个「Python 版 STARLIGHT」。
> 输入仍是光谱；换的是推断方式：用网络（或模拟推断）代替每条谱上的优化搜索。

---

## 1. 一句话

用大量合成光谱（以及传统拟合码当教师）训练一个推断模型，使新光谱在毫秒到秒级给出年龄、金属丰度、消光、星形成历史（SFH），并报告**校准过的不确定性**；用 pPXF / STARLIGHT 做对照，而不是宣称取代它们。

## 2. 这是什么学科

**观测天文 + 方法**（恒星种群 / 全谱拟合），深度学习是工具。

- 数据：星系积分光谱或 IFU 每个空间像素的光谱（可选加测光）。
- 科学量：质量加权/光度加权年龄、金属丰度、\(A_V\) 或 \(E(B-V)\)、分箱 SFH、质量光比。
- 论文形态：天文期刊方法栏（MNRAS / A&A / AJ）或 ML-for-Astro workshop；必须有与 pPXF（及可选 STARLIGHT）的定量对比。

不是：计算机视觉竞赛、纯网络结构论文、也不是重写拟合器去跟 pPXF 抢「标准软件」地位。

## 3. 问题为什么存在

传统全谱拟合（STARLIGHT、pPXF、FIREFLY 等）对**每一条**新光谱单独做优化。参数空间简并（年龄–金属丰度–尘埃），巡天规模（SDSS、LAMOST、DESI、MaNGA）下算力与一致性都成问题。

摊销推断把「搜索」的成本放到训练阶段：

1. 用 SSP 模板 + 各种 SFH / 尘埃 / 噪声合成带标签的光谱；
2. 训练 \(f_\theta\)：光谱 \(\rightarrow\) 种群参数（或后验）；
3. 部署时一次前向传播即可。

科学上它不自动比 pPXF「更对」：它对训练分布负责。论文的贡献必须说清：**在什么假设下快、准、误差可信，以及何时会失效。**

## 4. 别人已经做了什么（不要再做一遍）

| 工作 | 做了什么 | 对你的含义 |
| --- | --- | --- |
| Woo et al. 2024, MNRAS（StarNet vs FIREFLY / STARLIGHT / pPXF / pyPipe3D） | CNN 从光学 mock 出平均年龄、金属丰度、\(M_*/L\)、\(E(B-V)\)，极快；训练在 TNG SFH + E-MILES + 仿 SDSS 噪声上 | 「CNN 四个数 + 很快」这篇已结束 |
| 同文作者自述 | 计划把整条 SFH 纳入网络；强调网络只认识 TNG 宇宙与所用 SSP | 完整 SFH、域偏移是他们点名的后续 |
| A&A 2024, SBI + 光谱编码 | 摊销模拟推断，出 SFH 等量的**后验样本**，对照 pPXF | 「有不确定性的摊销 SFH」也已有入口论文 |
| 更新的 CNN（如 PHANGS 光谱+测光） | IFU + 多波段测光，分箱 SFH / 年龄–金属丰度关系 | 再做一个通用 CNN 更挤 |

**已关闭的题目：** 再训一个 CNN，在自己的 mock 上报更小的 MSE，宣称比 STARLIGHT 快。

## 5. 还值得做的切口（建议只选一个当主课题）

按「还能写成一篇方法文」而不是「还能发顶会」来排。建议主课题选 A，B/C 作备选。

### A. 教师校准 + 域偏移（最推荐）

**问题：** StarNet 类模型在「训练宇宙」里很好，换 SSP、换 SFH 先验、上真实巡天就漂。

**做法：**

- 合成谱预训练；
- 用 pPXF（主）和 STARLIGHT（辅，若能跑通二进制）在**同一批真谱**上当教师，做蒸馏或事后校准；
- 系统测：换 SSP 库、换噪声模型、有/无发射线、TNG vs 简单参数化 SFH；
- 必须有 **OOD 检测**：模型何时该拒绝给出年龄。

**产物：** 校准后的点估计或后验 + 失效图；不是新拟合软件。

**为什么适合你：** 你了解 STARLIGHT 在算什么，又有 DL；论文卖的是「传统码的加速与校准」，审稿人能懂。

### B. 校准过的 SFH 后验（更重统计）

在 A 的数据管线上做模拟推断（神经密度估计 / 流模型），输出分箱 SFH 的后验，做覆盖率检验（simulation-based calibration）。对照 pPXF 点估计。不要只画几条「看起来像」的 SFH。

### C. 具体巡天（例如 LAMOST）上的可复现流程

StarNet 对的是 SDSS 风格光学。换仪器响应、波长覆盖、分辨率、噪声，本身可以是贡献，但**必须**带域偏移实验，否则会被写成「我们在 LAMOST 上重复了 StarNet」。

## 6. 明确不做什么

- 不把网络命名或包装成「Python 版 STARLIGHT」。
- 不整合 pPXF / FIREFLY / Bagpipes 成超级库。
- 不把当前仓库的 NNLS 原型宣传成科研拟合器。
- 第一篇方法文不追求「所有巡天、所有参数、GUI 全家桶」。

当前 GitHub 仓库（`starlightpy`）最多当 **合成光谱 / 红化 / 读谱** 的小工具；拟合金标准用 pPXF（和可选的 STARLIGHT 二进制）。

## 7. 技术计划（按依赖顺序，不是按日历）

### 阶段 0 — 能复现对照，而不是能训网络

- 固定一条光学波长网格、一套 SSP（建议先 E-MILES 或与对照论文相同的库，版权/使用条款要核）。
- 用 pPXF 对一组公开 SDSS/MaNGA 谱跑通，保存 \(x_j\)、年龄、\(A_V\)。
- 若做 STARLIGHT 教师：同一批谱、同一套 base，只求「能出数」，不对齐也先记下来。

**完成标准：** 独立脚本，给定谱文件能复现表上的 pPXF 数字。

### 阶段 1 — 合成器（这是方法文的一半）

可控制地生成：

- 参数化 SFH 或从模拟抽 SFH；
- 前景尘埃（CCM / Calzetti）；
- 速度弥散卷积；
- 噪声：先高斯，再尽量用真实残差（StarNet 文指出纯高斯会低估金属丰度误差）。
- 发射线：先 mask，再单独做「未 mask」消融。

**完成标准：** 给定标签能复现光谱；标签与 pPXF 在无噪声极限下大致可逆（检验合成器没写错）。

### 阶段 2 — 基线摊销模型（点估计）

- 简单 1D CNN 或小型 Transformer，输出 4～8 个量（先平均年龄、[Z/H]、\(A_V\)，再加粗 SFH 箱）。
- 训练集 / 验证 / 测试按 **SFH 族** 划分，禁止随机打乱泄漏。
- 指标：偏差、散点、按 SNR / 真年龄分层（对照 Woo+2024 的图）。

**完成标准：** mock 测试集上有可重复数字；并做一次「换 SSP 再测」证明你会报失败。

### 阶段 3 — 论文真正的贡献（在 A/B/C 里只深挖一个）

**若选 A：**

- 教师损失：真谱上 \(\|f_\theta(O)-y_{\mathrm{pPXF}}\|\)，或只校准系统偏差。
- 域偏移矩阵：行 = 训练设置，列 = 测试设置。
- 拒绝作答：集成方差、密度估计尾部、或与重建残差挂钩。

**若选 B：** 后验采样 + SBC / coverage；与 pPXF 点估计并排，不声称「打败 pPXF」。

**完成标准：** 一张别人能一眼看懂的「何时可信」图 + 与传统码的并排表。

### 阶段 4 — 写作与开源

- 开源：合成配置、训练脚本、预训练权重、对照用的 pPXF 设置（版本钉死）。
- 正文必须写清：网络学习的是 **所用 SSP + 所用 SFH 先验**，不是「真实宇宙」。
- 引用：Woo+2024、Cappellari pPXF、Cid Fernandes STARLIGHT、所用 SSP 库。

## 8. 资源与技能

| 需要 | 说明 |
| --- | --- |
| pPXF | 主教师与主对照，必须会用 |
| SSP 库 | E-MILES / BC03 等，注意分发许可 |
| 公开光谱 | SDSS、MaNGA 或 LAMOST 一级数据 |
| GPU | 阶段 2 起；阶段 0–1 可以 CPU |
| STARLIGHT 二进制 | 可选，仅当你要「与旧中文组结果对齐」 |

不需要先把 `starlightpy` 做成完整拟合器。

## 9. 风险（写进开题就诚实）

- **简并：** 网络可以「看起来准」，实际是记住了训练先验；换先验就垮。应用域偏移实验约束自己。
- **教师也有偏：** pPXF 不是真值。蒸馏论文的声称只能是「与 pPXF 一致且快」，不能是「更接近真 SFH」，除非真值来自模拟且测试分布与训练不同。
- **数据泄漏：** 同一星系不同噪声实现进了训练和测试。
- **重复劳动：** 阶段 2 结束时若没有 A/B/C 的独特实验，就停，不要硬写「我们也很快」。

## 10. 成功时这篇论文在说什么

错误表述：「我们提出了 Python 版 STARLIGHT / 全面替代 pPXF 的深度学习库。」

正确表述：「在给定 SSP 与 SFH 先验下，摊销模型可在 \(10^{-3}\)–\(10^{0}\) 秒给出与 pPXF 一致的种群参数（及不确定性）；我们量化了换模板与上巡天时的偏差，并给出拒绝准则。」

## 11. 建议你怎么决定

1. 若半年内要交差、且没有稳定的 pPXF + 光谱数据条件：不要开这个课题，用 pPXF 做科学或先复现 Woo+2024。
2. 若有 GPU、能跑 pPXF、愿意读那几篇对照文：选 **切口 A**，阶段 0–1 没过关之前不要设计新网络。
3. 当前 starlight 仓库：仅保留合成与 IO；不要把课题做成继续开发通用拟合库。
